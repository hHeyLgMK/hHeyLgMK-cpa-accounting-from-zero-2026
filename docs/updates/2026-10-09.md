## Windows 首次启动修复：3.2.1.1

用户桌面启动原 3.2.1 EXE 时出现“无法生成设备证书”。在真实 Windows 环境复现后，修复以下两处问题：

- `CertStrToNameW` 原声明未指定 Unicode，错误传递了 ANSI 字符串。现在按 UTF-16 传递并检查两次编码调用的错误。
- 原生证书 API 默认创建的密钥无法导出为设备 PFX。现在显式创建可导出的 RSA 2048 位用户密钥，使用 SHA-256 签名，保存并重新加载 PFX，再释放临时密钥容器。

已有 PFX 继续加载，设备身份不因升级重新生成。仅端口冲突时显示退出旧程序的提示。新增 Windows 构建脚本、文件版本 `3.2.1.1` 与原生启动回归测试。

修复后的 EXE 已通过首次生成证书、私钥保存、重开后身份一致、TLS 1.2、本机 HTTP 网页及生产 TLS 同步接口检查；内嵌网页仍与 3.2.1 源码逐字节一致。Android APK 和六科 4,412 题保持不变。最新文件哈希见 [SHA256SUMS.txt](../../downloads/peer/SHA256SUMS.txt)。

接口依据：[Microsoft 字符编码与封送说明](https://learn.microsoft.com/dotnet/standard/native-interop/charset)、[CertCreateSelfSignCertificate](https://learn.microsoft.com/en-us/windows/win32/api/wincrypt/nf-wincrypt-certcreateselfsigncertificate)。
